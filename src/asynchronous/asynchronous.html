⚡ Asynchronous JavaScript

Hiểu rõ bất đồng bộ — từ Call Stack đến Event Loop

1. Bất đồng bộ là gì?

Đồng bộ (Synchronous): các lệnh chạy tuần tự, lệnh sau phải đợi lệnh trước xong.

Bất đồng bộ (Asynchronous): một tác vụ tốn thời gian được đẩy ra chạy ngầm, JS tiếp tục chạy code tiếp theo, khi tác vụ xong thì quay lại xử lý kết quả.

🍜 Ví dụ đời thường: Đun nước pha mì. Đồng bộ = đứng nhìn nồi nước sôi 5 phút. Bất đồng bộ = bật bếp rồi đi làm việc khác, khi nước sôi bếp "kêu" thì quay lại.

2. Tại sao JS cần bất đồng bộ?

JavaScript là single-threaded — chỉ có 1 luồng chạy code. Nếu mọi thứ đều đồng bộ:

const data = fetch("https://api.example.com"); // mất 3 giây
console.log(data); // ← trang web ĐƠ 3 giây ở đây!

→ User không click, không scroll, không gõ được gì trong 3 giây đó. 😱

→ Vì vậy các tác vụ tốn thời gian (gọi API, đọc file, timer) phải chạy bất đồng bộ.

3. Cơ chế hoạt động — Event Loop

Đây là "trái tim" của async JS. Gồm 4 thành phần:

┌─────────────────────┐ │ Call Stack │ ← JS chạy code đồng bộ, từng dòng └──────────┬──────────┘ │ gặp tác vụ async ▼ ┌─────────────────────┐ │ Web APIs │ ← Trình duyệt đảm nhiệm (timer, fetch...) └──────────┬──────────┘ JS KHÔNG đứng đợi ở đây │ xong → đẩy callback ▼ ┌─────────────────────┐ │ Callback Queue │ ← Hàng đợi callback chờ chạy └──────────┬──────────┘ │ ▼ ┌─────────────────────┐ │ Event Loop │ ← Khi Stack TRỐNG → lấy callback từ Queue └─────────────────────┘ đẩy vào Stack để chạy
✅ Quy tắc vàng: Callback trong Queue chỉ được chạy khi Call Stack đã trống hoàn toàn (code đồng bộ chạy hết).

4. Ví dụ thấy rõ bất đồng bộ

a) setTimeout cơ bản

console.log(1);
setTimeout(() => { console.log(2) }, 1000);
console.log(3);
1 3 ← chạy ngay 2 ← sau 1 giây mới in

Dù console.log(2) viết trước console.log(3), nhưng nó bị đẩy ra sau vì nằm trong setTimeout.

b) Bằng chứng rõ nhất: setTimeout 0ms

console.log("Start");
setTimeout(() => console.log("A - 0ms"), 0);
setTimeout(() => console.log("B - 1000ms"), 1000);
setTimeout(() => console.log("C - 500ms"), 500);
console.log("End");
Start End ← code sync chạy hết trước A - 0ms ← dù 0ms, vẫn phải đợi Stack trống C - 500ms B - 1000ms
⚠️ Hiểu lầm phổ biến: setTimeout(fn, 0) KHÔNG có nghĩa là "chạy ngay". Nó chỉ có nghĩa là "đẩy vào Queue, khi Stack trống thì chạy".

5. Promise — 3 trạng thái

Trạng thái Ý nghĩa
pending Đang chờ — chưa có kết quả
fulfilled Thành công — đã gọi resolve(value)
rejected Thất bại — đã gọi reject(error) 
const p = new Promise((resolve, reject) => {
    // Phần executor này chạy ĐỒNG BỘ ngay lập tức
    console.log("1. Executor chạy");
    setTimeout(() => {
        console.log("3. Trong setTimeout");
        resolve("OK"); // chuyển sang fulfilled
    }, 2000);
    console.log("2. Executor kết thúc");
});

console.log(p); // Promise {<pending>}

p.then(result => {
    console.log("4. .then chạy:", result);
});
1. Executor chạy 2. Executor kết thúc Promise {<pending>} ← đợi 2 giây 3. Trong setTimeout 4. .then chạy: OK
💡 Nhớ kỹ: Executor của Promise chạy đồng bộ ngay. Chỉ có .then() mới chạy bất đồng bộ (sau khi resolve).

6. Tổng kết cần nhớ

  • JS single-threaded → cần async để không block UI.
  • Async = "đẩy việc tốn thời gian ra chạy ngầm, làm tiếp việc khác".
  • Event Loop điều phối: chỉ chạy callback khi Call Stack trống.
  • setTimeout(fn, 0) ≠ chạy ngay, mà = "chạy sau khi sync xong".
  • Promise có 3 trạng thái: pending → fulfilled / rejected.
  • Executor của Promise chạy sync; .then() chạy async.
  • Các nguồn async phổ biến: setTimeout, fetch, addEventListener, Promise, async/await.
🎯 Bài tập tự luyện: Đoán output trước khi chạy, sau đó chạy để kiểm tra: 
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");

→ Đáp án: 1, 4, 3, 2 (microtask của Promise chạy trước macrotask của setTimeout).
